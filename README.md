# EMDR.dev - Development Playground

Welcome to EMDR.dev, a personal development playground where code meets creativity! This modern Next.js website serves as an experimental space for building cool projects, testing new technologies, and having fun with development.

## 🚀 Overview

EMDR.dev is designed as a creative sandbox for developers who love what they do. The site embodies a "fun-first" philosophy while providing a professional platform for:

- **Rapid Prototyping**: Quick setup for new projects with modern tooling - from idea to running code in minutes
- **Safe Experimentation**: A secure environment to test wild ideas and learn new technologies without breaking production
- **Creative Development**: Where development meets creativity, passion, and innovation

The platform solves the common problem of needing a reliable, modern development environment that's both powerful and enjoyable to use. Whether you're working on a weekend project or the next big thing, EMDR.dev provides the tools and environment to make it happen.

## ✨ Features

## 🛠 Getting Started

### Prerequisites

Before you begin, ensure you have the following installed:
- **Node.js 18+** - [Download from nodejs.org](https://nodejs.org/)
- **npm** or **pnpm** - Package manager (npm comes with Node.js)
- **Git** - [Download from git-scm.com](https://git-scm.com/)

### Installation

1. **Clone the repository**:
   ```bash
   git clone https://github.com/Addfunction/AddFuture.git
   cd AddFuture
   ```

2. **Install dependencies**:
   ```bash
   npm install --legacy-peer-deps
   ```
   > Note: The `--legacy-peer-deps` flag is used to handle dependency compatibility with the latest React version.

3. **Start the development server**:
   ```bash
   npm run dev
   ```

4. **Open your browser**:
   Navigate to [http://localhost:3000](http://localhost:3000) to see the site in action!

### Available Scripts

- `npm run dev` - Start the development server with hot reload
- `npm run build` - Build the application for production deployment
- `npm run start` - Start the production server (requires build first)
- `npm run lint` - Run ESLint to check code quality and style

## 📖 Usage

### Exploring the Site

1. **Landing Page**: Start at the hero section to understand the site's purpose and mission
2. **Features Section**: Discover the core capabilities - rapid prototyping, safe sandbox, and fun-first development
3. **Interactive Terminal**: Click the terminal icon to access the built-in development environment
4. **Call-to-Action**: Use the "Let's Code" and "Explore Projects" buttons to dive deeper into the platform

### For Developers

- **Project Setup**: Use the site as a starting point for new Next.js projects
- **Component Testing**: Experiment with the included UI components in the `components/` directory
- **Styling**: Customize the look and feel using the Tailwind CSS configuration
- **Development**: Make use of the TypeScript setup for type-safe development

### Customization

The site is built to be easily customizable:
- **Colors**: Modify the theme in `styles/globals.css`
- **Components**: Add or modify components in the `components/` directory
- **Pages**: Create new pages in the `app/` directory following Next.js 13+ app router conventions
- **Functionality**: Extend features by adding new API routes in `app/api/`

## 🤝 Contributing

We welcome contributions from developers who share our passion for creative, fun development! Here's how you can get involved:

### Ways to Contribute

1. **Bug Reports**: Found something broken? Open an issue with detailed steps to reproduce
2. **Feature Requests**: Have an idea for improvement? Submit a feature request
3. **Code Contributions**: Submit pull requests for bug fixes or new features
4. **Documentation**: Help improve this README or add inline code documentation
5. **UI/UX Improvements**: Enhance the visual design or user experience

### Contribution Guidelines

1. **Fork the repository** and create your feature branch from `main`
2. **Follow the existing code style** - we use TypeScript, ESLint, and Prettier
3. **Test your changes** thoroughly before submitting
4. **Write descriptive commit messages** explaining what and why
5. **Submit a pull request** with a clear description of your changes

### Development Setup for Contributors

1. Follow the installation steps above
2. Create a new branch: `git checkout -b feature/your-feature-name`
3. Make your changes and test them locally
4. Commit your changes: `git commit -m "Add your feature"`
5. Push to your fork: `git push origin feature/your-feature-name`
6. Submit a pull request through GitHub
